# YouTube Safe Kids — toxicity filter

Research artifact for the paper **"Toxicity Detection in Brazilian Portuguese Video
Transcripts: An Annotated Corpus, a Three-Level Classifier and a Verbal-Toxicity Score for
Children's Video Search"**.

This repository contains the annotated corpus, the training and evaluation code, the stored
result files, and the scripts that regenerate **every figure, table and number reported in
the paper**.

> **Note on the corpus.** The published corpus (`data/corpus_toxicidade_publico.csv`)
> carries the transcribed sentences, source-video metadata and the three independent
> annotations, enabling full end-to-end reproduction of all models and experiments.

---

## 1. What the paper claims and where to check it

No number in the manuscript was typed by hand. The tables are written by the scripts
below, and every number in the prose is a LaTeX macro generated by
`app/nlp/evaluation/scripts/gerar_numeros_artigo.py` from the stored result files. The
generated file, **`app/nlp/evaluation/results/video-v2/latex/numeros.tex`**, is the single
place to audit a number: each macro carries a comment saying what it is and which result
file it was read from. All result paths below are relative to
`app/nlp/evaluation/results/video-v2/` (the run tag: video-disjoint split, corpus v1 labels,
near-duplicate groups kept out of the experiments). `results/video-v1/` holds the earlier run
that still contained those groups; the paper uses it only to measure their effect.

| Claim in the paper | Script | Stored result |
|---|---|---|
| Corpus size, class balance, sentence length | `analisar_corpus.py` | `corpus/corpus_stats.json`; also checkable from the corpus file itself (Section 6) |
| Share of toxic sentences without profanity; lexicon rule | `analisar_corpus.py` | same file, section `decidibilidade_lexical` |
| Agreement: Fleiss' and Cohen's $\kappa$, per class and per batch; disagreement patterns | `analisar_anotacao.py` | `anotacao/` |
| Video-disjoint split (sizes, folds) | `app/nlp/datasets/gerar_particoes.py` | `data/particoes/particao_video.csv` |
| Near-duplicate groups: the rule, its stricter and looser variants, and their effect in the earlier run (`video-v1`) | `analisar_quase_duplicatas.py` | `quase_duplicatas_*.json`; the groups are marked in the column `quase_duplicata` of the corpus |
| Hyperparameter search (random search + 3-stage Successive Halving) and the selected configuration | `train_toxicity_gridsearch.py --mode search` | `toxicity_gridsearch/gridsearch_optimized_search_*.json` |

| Threshold chosen on out-of-fold predictions; calibration (ECE, Brier, temperature) | `analisar_calibracao_limiar.py` | `calibracao_limiar_*.json` |

`gerar_numeros_artigo.py` ends with a cross-check between sources: it confirms that the
test-set size is the same in every result file and that all files come from the same run,
and writes any mismatch as a comment in `numeros.tex`. A result file that is missing leaves
its macros undefined, so the manuscript fails to compile at the exact place where the
number would go, rather than showing a stale value.

## 2. Requirements

- Python 3.9+
- A YouTube Data API key (only for the live service; **not** needed to reproduce the
  model results or the search case study, whose excerpts were collected by hand and are
  stored in `data/reordenacao_buscas.csv`)
- A CUDA GPU is strongly recommended for fine-tuning. The paper's run used one consumer
  GPU (named in `latencia_*.json`); the whole pipeline took several hours, most of it in
  the hyperparameter search

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # then fill in YOUTUBE_API_KEY
```

### Model weights to download

**No model weights ship with this repository**, and none are in version control: they are
either downloaded from third parties or produced by training. About **8 GB** in total, but
you only need what the step you are running asks for.

| Weights | Identifier | Size | Needed by |
|---|---|---:|---|
| BERTimbau Base (cased) — the backbone that is fine-tuned | `neuralmind/bert-base-portuguese-cased` | 438 MB | `busca`, `final`, `sem_finetuning`, `comparacao` |
| HateBR offensive-language classifier | `ruanchaves/bert-base-portuguese-cased-hatebr` | 436 MB | `sem_finetuning` |
| Toxicity target classifier (targeted vs. untargeted) | `dougtrajano/toxicity-target-classification` | 436 MB | `sem_finetuning` |
| Llama 3.1 8B, served locally | `ollama pull llama3.1:8b` | 4.9 GB | `llm`, `latencia` |
| Detoxify multilingual checkpoint (XLM-RoBERTa base) | `multilingual_debiased-0b549669.ckpt` | 1.1 GB | `detoxify` |
| BERTimbau Large — *optional*, only if you change the backbone | `neuralmind/bert-large-portuguese-cased` | 1.3 GB | — |

**BERTimbau Base** downloads itself on first use: `from_pretrained` writes it to
`app/nlp/models/cache/`, the path set by `cache_dir` in `app/nlp/config.py`. Nothing to do
in advance, but the first run needs network access.

**The two off-the-shelf classifiers of step 5 do not download themselves.** The script
reads them from local directories, so fetch them once:

```bash
pip install "huggingface_hub[cli]"
hf download ruanchaves/bert-base-portuguese-cased-hatebr \
    --local-dir data/models/ruanchaves_bert_base_hatebr
hf download dougtrajano/toxicity-target-classification \
    --local-dir data/models/dougtrajano_toxicity_target_classification
```

The directory names matter: `app/nlp/training/train_toxicity_sem_finetuning.py` looks for
exactly those two paths under `data/models/`.

**Llama 3.1 8B** runs through [Ollama](https://ollama.com), locally and offline — no cloud
API is involved. Install Ollama, then `ollama pull llama3.1:8b` and `ollama serve`. The
host can be overridden with `OLLAMA_HOST` (default `http://localhost:11434`).

**Detoxify** (`pip install detoxify==0.5.3`, already in `requirements.txt`) downloads its
multilingual checkpoint on first use, from the project's GitHub release, into the
`torch.hub` cache (`~/.cache/torch/hub/checkpoints/`); the first run needs network access.
The file name carries the start of its sha256, and `docs/external-models.md` gives the
full hash of the copy used.

**The fine-tuned classifier** is not downloadable: it is the output of the `final` step,
written to `app/nlp/models/trained/<tag>/`. Reproducing it means running the search or, for
the selected configuration alone, the `final` step
(`python -m app.nlp.training.train_toxicity_gridsearch --mode final`): it reads the
configuration from `best_config` in the most recent stored search file. That configuration is the
winner of the stability stage (highest mean macro F1 across seeds), which need not be the
leader of stage 2; the search file records both.

Everything above is regenerable, which is why `.gitignore` excludes `models/cache/`,
`models/trained/`, `*.bin` and `*.safetensors`. Do not commit weights.

## 3. Reproducing the paper

> **Read this first.** The pipeline reads `data/corpus_toxicidade_publico.csv`, the file
> distributed here, which carries all 1,811 transcribed sentences and their annotations,
> and the stored split `data/particoes/particao_video.csv`. It runs end-to-end from a clean
> clone, with no data to obtain beyond the model weights of Section 2. The experiments use
> the 1,577 sentences that remain once the 234 sentences of the near-duplicate groups
> (column `quase_duplicata`) are set aside; the runner does this by default
> (`--rotulagem v2`), and `--rotulagem v1` reproduces the earlier run with them.

### One command

Run from this directory:

```bash
python scripts/rodar_rodada_toxicidade.py --particao video
```

This runs every step below in order, each as a separate process, and writes everything to
`app/nlp/evaluation/results/video-v2/`: one log per step in `logs/`, and a summary with the
status and duration of each step in `rodada_<timestamp>.json`. If the search or the
final-model step fails, the steps that need the model are skipped; any other failure is
logged and the run continues. Useful options: `--pular llm` (no Ollama),
`--sem-busca` (reuse the stored search and start from the final model).

Nothing is written into the manuscript folder by the run: tables and figures go to
`results/video-v2/latex/`.

### Steps

| Step | Command (from `src/`) | Needs |
|---|---|---|
| `busca` | `python -m app.nlp.training.train_toxicity_gridsearch --mode search` | GPU |
| `final` | `python -m app.nlp.training.train_toxicity_gridsearch --mode final` | GPU |
| `avaliacao` | `python -m app.nlp.evaluation.evaluate_toxicity` | GPU (or CPU, slower) |
| `baselines` | `python -m app.nlp.training.train_toxicity_baselines` | CPU |

| `dispersao` | `python app/nlp/evaluation/scripts/analisar_dispersao.py` | — |
| `sem_finetuning` | `python -m app.nlp.training.train_toxicity_sem_finetuning --modo tudo` | GPU recommended; the two classifiers of Section 2 |
| `llm` | `python -m app.nlp.training.train_toxicity_llm_baselines --models llama3.1:8b` | Ollama |
| `detoxify` | `python app/nlp/evaluation/scripts/avaliar_detoxify.py` | GPU recommended; the Detoxify checkpoint |
| `comparacao` | `python -m app.nlp.evaluation.scripts.comparar_modelos` | — |

| `latencia` | `python -m app.nlp.evaluation.scripts.medir_latencia` | GPU, Ollama |

Scripts invoked by file path rather than with `-m` do not need PyTorch, and are run that way
on purpose: importing the package `app.nlp.evaluation` loads PyTorch, which costs about
2 GB of memory and can make a concurrent GPU job run out of memory on a 16 GB machine.

`comparar_modelos.py` reads the stored test predictions of the final model (every seed) and
of the tuned baselines, re-trains the fixed baselines (deterministic) and fits the linear
probe, so it runs after `final` and `baselines_ajustadas`. `analisar_dispersao.py` reads
the search, the final model and both baseline files. The tuned baselines take about an hour
on CPU, almost all of it in logistic regression.

### Seeds and determinism

- Split: drawn once with `StratifiedGroupKFold`, seed 42, and stored; every script reads the
  stored file instead of recomputing it.
- Search: configurations sampled with seed 42; the stability stage re-trains the three best
  with seeds 42, 7 and 2024 (`SEARCH_SEEDS` in `train_toxicity_gridsearch.py`).
- Final model: trained with several seeds (option `--sementes`); the reference model used
  by every downstream analysis is the one trained with the first seed, and the paper reports
  the test macro F1 as the mean and standard deviation across seeds.
- Fine-tuning on a GPU is not bit-for-bit deterministic across hardware and library
  versions, so a re-run reproduces the reported figures up to that variation; the
  seed-to-seed deviation reported in the paper gives its expected size. The classical
  baselines, the statistics and every analysis that reads stored predictions are
  deterministic.

### Numbers, tables and figures

After a run, regenerate what the manuscript reads:

```bash
python app/nlp/evaluation/scripts/gerar_numeros_artigo.py
python -m app.nlp.evaluation.scripts.gerar_figuras_artigo --idioma en --duas-colunas
python -m app.nlp.evaluation.scripts.regerar_tabelas_estudo_caso --idioma en --duas-colunas
python -m app.nlp.evaluation.scripts.gerar_figura_conceitual --idioma en
```

They write to `results/video-v2/latex/`, except `gerar_figuras_artigo.py`, which writes
its figures and most of its tables to `results/video-v2/artigo/`. Setting `YSK_ESCREVER_LATEX=1` makes them write
into the manuscript folder instead; that is how the authors update the paper, as a
deliberate step after checking a run.

The paper cites three tables and four figures that it does not print (Tables S1–S3,
Figures S1–S4). They are in [`supplementary/supplementary.pdf`](supplementary/supplementary.pdf),
which `supplementary/supplementary.tex` builds directly from the files above
(`results/video-v2/artigo/` and `results/video-v2/latex/`), with no number typed by hand.
After regenerating them, rebuild it with `cd supplementary && latexmk -pdf supplementary.tex`.

`regerar_tabelas_estudo_caso.py` rebuilds the case-study outputs from the stored JSON
files, so it works **without** the trained model — useful for checking the tables without
re-running the fine-tuning. Dropping `--idioma en` regenerates everything in Portuguese.

## 6. Data

Three datasets are distributed here.

`data/corpus_toxicidade_publico.csv` — 1,811 annotated sentences drawn from 206 public
YouTube videos, semicolon-separated, UTF-8 (corpus v1). **It carries the transcribed sentence itself**,
which is what makes the resource reusable rather than merely auditable: the classifier can
be retrained, the annotation inspected item by item and the Mild/Severe boundary recomputed
from the individual labels. A corpus whose sentences were withheld would support none of
that, since the annotation is attached to one specific transcription and a transcription is
not recoverable from a video identifier.

`data/reordenacao_buscas.csv` — the 40 videos of the search case study, with the query, the
position the platform returned them in, the metadata and the three sampled transcript
excerpts.

`data/reordenacao_rotulos_humanos.csv` — the labels the three raters of the corpus gave the
120 sampled excerpts of the case study (`item;estrato;termo;posicao;video_id;janela;frase;P1;A1;P2;tox`).
Each rater worked alone and blind: the excerpts were shown in shuffled order, without the
video, the query, the stratum or the prediction, under the corpus guideline. `tox` is the
majority of the three (no excerpt lacked one). These are labels of the sampled excerpts, not
of the videos, and say nothing about the parts of a video that were not sampled.

Two other files the scripts mention are deliberately absent and are not needed here.
`corpus_toxicidade.csv` is the authors' working copy of the same corpus; the pipeline falls
back to the published file when it is missing, which is the normal case in a clone.
`corpus.csv` and `corpus_analise_sentimentos.csv` belong to the Sentiment Analysis filter —
a separate study that shares this codebase, since the service is modular — and nothing in
Section 3 touches them.

| Column | Meaning |
|---|---|
| `id_sentenca` | stable row identifier, 1–1811 |
| `video_id` | YouTube video identifier |
| `titulo` | video title, as published |
| `parte` | which part of the video the sentence came from: `Início`, `Meio`, `Fim` |
| `link` | video URL |
| `frase` | the transcribed sentence |
| `n_palavras` | length of the sentence in words |
| `tem_palavrao` | 1 if the sentence matches the profanity lexicon used in the paper, else 0 |
| `tox` | **final label**, the mode of the three annotations |
| `p1`, `p2`, `a1` | the three independent annotations, pseudonymised (P1 professor, P2 psychologist, A1 student) |
| `lote` | annotation batch: `1` (1,236 sentences) or `2` (575 sentences, drawn among sentences more likely to be offensive) |
| `quase_duplicata` | 1 if the sentence belongs to a near-duplicate group: its last three words, after lowercasing and removing accents and punctuation, are shared by at least four sentences of the corpus. The 234 marked sentences are published but kept out of every experiment |

Labels: `Nenhuma` (None) — appropriate; `Leve` (Mild) — indirect offensiveness, aimed at
objects, situations or abstract entities; `Severa` (Severe) — direct offensiveness, aimed
at a person or group. The distinction that separates Mild from Severe is the **target** of
the offence, not its intensity. The full guideline given to the raters, in Portuguese and
in English, is in [`docs/annotation-guideline.md`](docs/annotation-guideline.md).

Three annotators labelled every sentence independently, seeing only the sentence; the final
label is the mode, and when the three labels differ the label of P1 is used. Each sentence
was labelled once, with no adjudication round. Agreement: 78.7% unanimous, 85.8% pairwise,
Fleiss' $\kappa$ = 0.7809. Three sentences (0.2%) received three distinct labels.

### Split

`data/particoes/particao_video.csv` is the split used by every experiment in the paper
(`id_sentenca;video_id;particao;fold_k5;fold_k2;quase_duplicata`). It is grouped by video:
every sentence of a video is on the same side of the train/test split and in the same
cross-validation fold. Over the published corpus, test: 417 sentences from 44 videos;
training: 1,394 sentences from 162 videos. Once the near-duplicate groups are set aside, as
in every experiment of the paper, the test set has 358 sentences from 44 videos and the
training set 1,219 sentences from 162 videos; no video moves. It was drawn once with
`StratifiedGroupKFold` (seed 42) by `app/nlp/datasets/gerar_particoes.py`, before the
near-duplicate groups were identified, and is read, not recomputed, by every script. `particao_frase.csv` reproduces the
sentence-level split of the first submission and is kept only for reference.

### What the published columns let you verify

`n_palavras` and `tem_palavrao` are computed with exactly the definitions used in the paper,
so the corpus claims can be checked from the published file without running the pipeline:

| Claim in the paper | Reproduced from |
|---|---|
| 1,811 sentences, 206 videos | row count, distinct `video_id` |
| mean length 8.4 words, median 7 | `n_palavras` |
| class balance 44.8/28.9/26.3 (812/523/476) | `tox` |
| 78.7% unanimity, 85.8% pairwise, Fleiss' $\kappa$ = 0.7809 | `p1`, `p2`, `a1` |
| per-batch kappa 0.8009 and 0.7307 | `p1`, `p2`, `a1` × `lote` |
| 22.2% of sentences contain profanity (402) | `tem_palavrao` |
| 64.1% of toxic sentences carry none (640) | `tem_palavrao` × `tox` |
| 5.3% of non-toxic sentences do (43) | `tem_palavrao` × `tox` |
| lexicon rule reaches 0.60 macro F1 | `tem_palavrao` × `tox` |
| in the 1,577 sentences of the experiments: 54.2% of toxic sentences carry no profanity (415), and the lexicon rule reaches 0.69 | the same, over the rows with `quase_duplicata` = 0 |

### Notes on the data

- Sentences are transcriptions of **speech from public videos**, obtained with an external
  transcription tool. They were brought to one written form: speaker-change marks (`>>`)
  and non-speech tags such as `[Música]` were removed, and swear words masked in the source
  text (asterisks or `[ __ ]`) were restored from their initial letter and the context. No
  other word was edited, so recognition errors remain in the text the annotators read.
- The corpus holds **no personal data** about children or caregivers. Video identifiers,
  titles and URLs are public metadata.
- Annotator columns are pseudonymous.
- Every sentence is distinct; there are no duplicates.

### Provenance and redistribution

The sentences were transcribed from the audio of publicly available YouTube videos. Each row
identifies its source video and carries the link, so the provenance of every annotated
sentence is traceable. No video, audio or subtitle file is redistributed: what is published
are short excerpts of speech, reproduced as quotation for research purposes.

The same holds for the search case study of the paper. `data/reordenacao_buscas.csv`,
`data/reordenacao_rotulos_humanos.csv` and the stored result file
`results/video-v2/estratos_*.json` keep every score, class, ranking and statistic **and** the
120 sampled excerpts with their human labels, so
`regerar_tabelas_estudo_caso.py` rebuilds the tables and figures and
`analisar_estratos.py` reproduces the qualitative failure analysis, both from the stored
files alone.

This publishing decision has a licensing consequence, set out in Section 8: the transcribed
text is not the authors' to license, so the MIT grant does not cover it.

## 9. Anonymity

The journal this work targets, JBCS, operates **single-blind** review: reviewers see the
authors' identities, and the manuscript itself carries names and affiliations. This
repository therefore **does not need to be anonymous**, and making it anonymous would be
inconsistent with the submitted PDF.

If a double-blind venue is targeted later, what would need removing is limited: this file's
citation and license sections, `CITATION.cff`, and the institutional references in
`app/nlp/README.md`. No author name appears anywhere in the source code.
